## Требования

- Go 1.22+
- Проект должен компилироваться и проходить `go test ./...` до запуска обфускатора

## Установка

```bash
git clone https://github.com/zefixed/pop-go
cd pop-go
go build -o pop-go ./cmd
```

## Быстрый старт

Минимальный запуск — переименование идентификаторов, XOR-шифрование строк, сборка под Linux amd64:

```bash
./pop-go \
  --target-path ./myproject \
  --output-path ./dist \
  --binary-name myapp \
  --identifiers \
  --literals --literals-level easy \
  --goos linux --goarch amd64
```

Полная обфускация через конфиг-файл:

```bash
./pop-go -c config/config.maximum.json \
  --target-path ./myproject \
  --output-path ./dist \
  --binary-name myapp \
  --goos linux --goarch amd64
```

## Флаги CLI

Флаги всегда перекрывают значения из конфиг-файла.

### Основные

| Флаг | По умолчанию   | Описание                                                                  |
|------|----------------|---------------------------------------------------------------------------|
| `-c, --config` | —              | Путь к JSON конфиг-файлу                                                  |
| `-t, --target-path` | —              | Путь к корню проекта (где лежит `go.mod`)                                 |
| `-o, --output-path` | `.`            | Куда сохранить скомпилированный бинарь                                    |
| `--binary-name` | имя директории | Имя выходного бинарного файла                                             |
| `-s, --seed` | `0`            | Сид ГПСЧ. `0` — уникальная сборка, любое другое число — детерминированная |
| `--test` | `true`         | Запускает `go test ./...` до и после обфускации                           |
| `--remove-temp` | `true`         | Удаляет временную директорию после завершения                             |
| `--temp-dir` | —              | Явно задает путь для временных файлов                                     |
| `-l, --lang` | `en`           | Язык сообщений логгера (`en`, `ru`)                                       |

### Преобразования

| Флаг | Описание |
|------|----------|
| `--delete-comments` | Удалить все комментарии из исходного кода |
| `--identifiers` | Переименовать неэкспортируемые идентификаторы |
| `--control-flow` | Выровнять поток управления (CFF) |
| `--literals` | Зашифровать строковые литералы |
| `--literals-level` | Профиль шифрования: `easy` (XOR) или `medium` (AES-CTR) |

### Сборка

| Флаг | По умолчанию | Описание |
|------|-------------|----------|
| `--goos` | `windows` | Целевая ОС |
| `--goarch` | `amd64` | Целевая архитектура |
| `--builder-flags` | `-ldflags -s -w -trimpath` | Флаги, передаваемые в `go build` |

### Логирование

| Флаг | По умолчанию | Описание |
|------|-------------|----------|
| `--log-level` | `info` | Уровень логирования: `debug`, `info`, `warn`, `error` |
| `--log-type` | `text` | Формат: `text` или `json` |
| `--enable-log-file` | `false` | Писать логи в файл |
| `--log-file` | `.log` | Путь к файлу логов |

## Конфиг-файл

Конфиг-файл в формате JSON задаёт значения по умолчанию. Флаги CLI их перекрывают.

```json
{
  "app": {
    "lang": "ru",
    "remove_temp": true,
    "test": true
  },
  "log": {
    "level": "info",
    "type": "text"
  },
  "obfuscator": {
    "target_path": "/path/to/project",
    "seed": 0,
    "comments":    { "enable": true  },
    "identifiers": { "enable": true  },
    "control_flow":{ "enable": true  },
    "literals":    { "enable": true, "level": "medium" }
  },
  "builder": {
    "flags": ["-ldflags", "-s -w", "-trimpath"],
    "goos": "linux",
    "goarch": "amd64",
    "output_path": "./dist",
    "binary_name": "myapp"
  }
}
```

Готовые конфиги лежат в папке `config/`:

| Файл | Описание                                  |
|------|-------------------------------------------|
| `config.base.json` | Комментарии + идентификаторы + XOR-строки |
| `config.extended.json` | Base + AES-строки                         |
| `config.maximum.json` | Extended + CFF                            |

## Преобразования

### Удаление комментариев (`--delete-comments`)

Удаляет все doc-комментарии и inline-комментарии из исходных файлов.

### Переименование идентификаторов (`--identifiers`)

Заменяет имена всех неэкспортируемых символов (функции, типы, переменные, поля структур, методы) на случайные строки длиной 16–32 символа.

Особые случаи:
- Методы интерфейсов и реализующих их структур получают **одинаковое** новое имя — интерфейс не ломается.
- Встроенные (анонимные) поля и соответствующий `TypeName` тоже синхронизируются.
- Внутренние `_test.go` файлы (с `package foo`, не `package foo_test`) переименовываются вместе с исходниками, чтобы тесты после обфускации компилировались.

### Выравнивание потока управления (`--control-flow`)

Превращает тело функции в диспетчер на основе `for`/`switch` с синтетической переменной-состоянием. Каждый оператор исходной функции становится отдельным `case`. Статический анализ потока управления становится значительно сложнее.

Функции пропускаются если содержат:
- горутины или операции с каналами
- `goto` / метки
- локальные `const` или `type` объявления
- type assertion на анонимный struct

### Шифрование строк (`--literals`)

Шифрует строковые литералы на этапе компиляции и заменяет их вызовом inline-функции дешифрования, встроенной в тот же файл.

| Уровень | Алгоритм | Описание |
|---------|----------|----------|
| `easy` | XOR | Один байт-ключ, без зависимостей |
| `medium` | AES-CTR | 32-байтный ключ + 16-байтный IV, встроены в код |

Не шифруются: пустые строки, struct-теги, import-пути, директивы компилятора (`//go:`), аргументы type conversion.

## Как это работает

1. Загружается конфигурация, инициализируется логгер
2. Проект копируется во временную директорию
3. Если `--test`: запускается `go test ./...` на оригинале
4. Пакеты загружаются с полной информацией о типах (`go/packages`)
5. Применяются преобразования в порядке: комментарии -> идентификаторы -> CFF -> строки
6. Изменённые AST записываются на диск через `go/format`
7. Если `--test`: запускается `go test -vet=off ./...` на обфусцированной копии
8. Запускается `go build` с указанными флагами

## Ограничения

- Обфускация применяется только к **неэкспортируемым** идентификаторам. Экспортируемый API не изменяется.
- Поля структуры с одинаковым именем в разных структурах, получившие разные новые имена, не переименовываются в тест-файлах (безопасный fallback — тест упадёт с ошибкой компиляции только для таких конкретных обращений).
- CFF не обрабатывает функции с горутинами, каналами и рядом других конструкций — они остаются без изменений.
